# State channel — how our Client half can read Host-only upload state

**Question.** The user wants the Settings UI to show *which Session logs have been uploaded*. The Host
half keeps that per-Session state in `$DSH_HOME/session-log-upload/watermarks.json`
(`{ version, sessions: { "<sessionId>": { afterSeq, sessionFormatVersion, updatedAt } } }`,
`host/watermark.js:8-11`). What is the sanctioned way for our Client half to read it?

**Scope of this document.** Reconnaissance only. No plugin code was changed. Every claim below is
either quoted from a shipped file (path + line), read from a live inspect contract, or marked
**UNVERIFIED** with what was tried.

> **Line-number caveat for our own files.** Citations into the **shipped** Harness under
> `...\app.asar\dsh\node_modules\@deepseek-ai\` are stable. Citations into **this** workspace
> (`index.js`, `client.js`, `host/watermark.js`) were read between 22:38 and 22:48 and `index.js` was
> edited by another teammate at 22:48:22, after this document was drafted. Where a `index.js` line
> number is now wrong, the stable anchor is the symbol name — `export const name`,
> `export const inject`, `export const COMMAND_NAME`, `function registerCommand`,
> `function statusText` — all of which still exist verbatim.

## 1. Candidate 1 — a typert Remote

### 1.1 What the shipped generated artifact looks like

`dsh-api-remote-access/lib/typert.host.js:1-2` — the header states the whole problem:

```js
/* Generated by @deepseek-ai/dsh-typert-generator from FaceModel — do not edit. */
import { z } from 'zod'
```

and it must export a `TYPERT` record (`:75-80`) of the shape
`{ package, face: 'host', schemas, get invocations(), model }` — the `model` being a full
`TypertPackageModel` of service/member/type reflection (that file is 238 lines, most of it model).
Every result codec is `{ mode: 'strict', typeSymbol, create, jsonSchema }` with a Zod factory
(`:63-69`).

The loader validates exactly that: `dsh-typert-loader/README.md` —

> “A manifest must name its exporting package, carry face `host`, hold schema factories, and contain
> well-formed reflection records; **invocation descriptors require strict codecs with factories**.”

### 1.2 Verdict 1a — `ctx.typert.register()` is impossible for us. Three independent blockers.

1. **No schema builder.** `TypertSchemaFactory.create: () => z.ZodType` (**[LIVE]** `typert` Service
   contract) and the generated files `import { z } from 'zod'` by **bare specifier**. Our bundle may
   not import bare specifiers, and the profile's `node_modules` contains no `@deepseek-ai` scope and
   no `zod` (`docs/api-dossier.md` §6.3). A hand-rolled `parse` stand-in would be a lie about the
   contract, not a substitute.
2. **No reflection model.** `TypertContribution.model` is a `TypertPackageModel` of member
   signatures, JSDoc, and type declarations. Nothing in plain JS produces that.
3. **The decorators are a build transform.** The shipped Host classes reach `Remote` through a
   compiled form: `dsh-api-account-controller/lib/index.js:44,57,60,203` —

   ```js
   let _classSuper = TypertRemoteService;
   return class AccountController extends _classSuper {
     const _metadata = typeof Symbol === "function" && Symbol.metadata ? Object.create(_classSuper[Symbol.metadata] ?? null) : void 0;
     _getState_decorators = [Remote];
     …
     constructor(ctx) {
       super(ctx, "accountController", { namespace: "account" });
       __runInitializers(this, _instanceExtraInitializers);
     }
   ```

   `__runInitializers` is the TC39 stage-3 decorator-initializer helper. That pass is a build step.

**Also decisive for the design, not just the mechanism:** the Client side of this path is generated
too. `dsh-api-account-controller/lib/typert.remote-client.js:1-2` is likewise
`/* Generated by @deepseek-ai/dsh-typert-generator from the Host FaceModel — do not edit. */` with
`import { z } from 'zod'`. And `dsh-api-gateway/README.md` (Known Limitations) closes the door:

> “**Every Client-supplied field requires a strict generated codec when its contribution mounts. SRC
> markers have no Client type projection and are not normal Client contribution inputs.**”

So: **a typert Remote in the `ctx.typert.register` sense is a blocker for us. Do not present it as
viable.** Any proposal that needs the Typert generator, a decorator pass, or a `lib/**/typert*.js`
artifact requires a build step this plugin does not have.

### 1.3 Verdict 1b — the Gateway's SRC fallback IS reachable from plain JS, with no build

This is the part that *does* work, and it is a documented escape hatch, not a hack. The Gateway
resolves a Remote endpoint in two steps (`dsh-api-gateway/lib/index.js:1255-1260`):

```js
resolveDescriptor(namespace, method, endpoint) {
  const strict = this.ctx.typert.local.get(endpoint);
  if (strict !== void 0) return strict;
  if (this.ctx.typert.local.hasSeen(endpoint)) throw new TypertGatewayError("gateway/definition-unavailable", endpoint, "its strict definition was withdrawn and SRC fallback is forbidden");
  return this.resolveSrcDescriptor(namespace, method, endpoint);
}
```

`resolveSrcDescriptor` (`:1261-1279`) scans **live Cordis services** for a `typertRemote` binding
whose `namespace` matches, and for a matching Remote marker:

```js
for (const [serviceKey, definition] of Object.entries(this.ctx.reflect.props)) {
  if (definition.type !== "service") continue;
  const receiver = this.ctx.get(serviceKey);
  if (!isObject(receiver)) continue;
  const original = originalOf(receiver);
  const value = Reflect.get(original, "typertRemote");
  if (value === void 0) continue;
  const binding = readBinding(value, original, serviceKey, endpoint);
  if (binding.namespace !== namespace) continue;
  const marker = remoteMethods(original).find((candidate) => (candidate.exportName ?? candidate.method) === method);
  if (marker === void 0) continue;
  candidates.push(this.srcDescriptor(binding, marker, method, endpoint));
}
```

The synthesized descriptor uses `src-json` codecs throughout (`:1296,1302,1317,1330`) and reads the
parameter list by parsing the method's own source text (`methodParameterNames`, `:1746-1774`), which
requires only *standard public class-method syntax*:

> “SRC method … must use unique identifier parameters without destructuring, defaults, or rest”
> (`:1774`).

**Every ingredient is plain data, so plain JS can produce it.**

The marker key is a stable string constant, deliberately readable across copies of the package:

> “[`mark`] uses a stable string property name, so another installed copy of the protocol package can
> read the same markers.” — `dsh-typert-protocol/README.md`
> `const REMOTE_METHOD_DESCRIPTOR = "@deepseek-ai/dsh-typert-protocol/remote-methods";`
> — `dsh-typert-protocol/lib/index.js:315`

and the reader/writer are pure functions over the prototype (`:424-470`):

```js
function remoteMethods(service) {
  const prototype = Object.getPrototypeOf(service);
  if (prototype === null) return [];
  return (readRemoteMethodDescriptor(prototype)?.methods ?? []).map((marker) => ({ ...marker }));
}
function readRemoteMethodDescriptor(prototype) {
  const property = Object.getOwnPropertyDescriptor(prototype, REMOTE_METHOD_DESCRIPTOR);
  if (property === void 0) return void 0;
  const descriptor = property.value;
  …
  const version = Reflect.get(descriptor, "version");
  if (version !== 1) throw new TypeError(`typert-protocol: unsupported Remote method descriptor version ${String(version)}`);
  const methods = Reflect.get(descriptor, "methods");
  if (!Array.isArray(methods)) throw new TypeError("typert-protocol: Remote method descriptor methods must be an array");
  return descriptor;

```

The binding is likewise a plain frozen record — `bindTypertRemote` returns
`Object.freeze({ service, serviceKey, namespace })` (`:326-337`), and `readBinding` only checks those
three fields (`dsh-api-gateway/lib/index.js:1738-1741`).

#### Concrete, complete registration snippet (no imports, no build)

```js
// host/ledger-service.js — plain ESM, dependency-free.
const MARKER = '@deepseek-ai/dsh-typert-protocol/remote-methods'

/** One unary Remote method: `sessionLogUpload/ledger`. */
class SessionLogUploadLedger {
  constructor(readWatermarks) {
    this.readWatermarks = readWatermarks
    this.name = 'sessionLogUploadLedger'
    // Exactly what bindTypertRemote() returns, written by hand:
    // readBinding requires value.service === the ORIGINAL service object.
    this.typertRemote = Object.freeze({
      service: this,
      serviceKey: this.name,
      namespace: 'sessionLogUpload',
    })
  }

  /** @returns {{sessions: Array<{sessionId: string, afterSeq: number, sessionFormatVersion: number, updatedAt: number}>}} */
  ledger() {
    return { sessions: this.readWatermarks() }
  }
}

// The marker must be an OWN property of the instance's immediate prototype.
Object.defineProperty(SessionLogUploadLedger.prototype, MARKER, {
  configurable: true,
  value: Object.freeze({
    version: 1,
    methods: Object.freeze([
      // exportName omitted when it equals the method name; mode omitted for a unary method.
      Object.freeze({ method: 'ledger', invocation: Object.freeze({ kind: 'direct' }) }),
    ]),
  }),
})

/**
 * @param ctx the plugin context.
 * @param readWatermarks () => array of {sessionId, afterSeq, sessionFormatVersion, updatedAt}.
 */
export function registerLedgerService(ctx, readWatermarks) {
  const service = new SessionLogUploadLedger(readWatermarks)
  // ctx.provide is mixin'd onto the context: cordis ReflectService does
  // `this.mixin("reflect", ["get","set","provide","accessor","mixin"])`
  // (cordis/lib/index.js:1320-1326) and it declares the name as `{ type: "service" }`
  // (cordis/lib/index.js:1384-1388) — which is precisely what resolveSrcDescriptor scans for.
  return ctx.provide(service.name, service, () => true)
}
```

Call it from `apply()` and chain the returned disposer into the existing `disposers` array.

Why each requirement is satisfied, with citations:

| Requirement | Where it is enforced | Why the snippet passes |
|---|---|---|
| name appears in `ctx.reflect.props` with `type: 'service'` | `cordis/lib/index.js:1384-1388` | `ctx.provide(name, …)` sets `props[name] = { type: "service" }` |
| resolvable by key from the Gateway | `cordis/lib/index.js:1347-1356` | `_getImpl` looks the name up in the **flat** `store` keyed by isolation symbol, so a service provided in *any* active fiber resolves |
| `typertRemote.service` is the *original* object | `dsh-api-gateway/lib/index.js:1738-1739`, `1742-1745` | the binding is built with `service: this` in the constructor |
| marker on the immediate prototype, own property | `dsh-typert-protocol/lib/index.js:425`, `430` | `Object.defineProperty(Class.prototype, KEY, …)` |
| descriptor `{ version: 1, methods: [...] }` | `:433-438` | exactly that shape |
| simple identifier parameters | `dsh-api-gateway/lib/index.js:1746-1774` | `ledger()` takes none |
| the endpoint is **claimed** over `/api` | `dsh-api-gateway/lib/index.js:907-914`, `926-939` | `collectSrcClaims()` adds `namespace/exportName\|method` for every marker |

**Two cache/lifecycle details that matter, and both are handled:**

- The SRC claim set is cached (`this.srcClaims ??= this.collectSrcClaims()`, `:912`) — but it is
  invalidated on *any* service change: `ctx.on("internal/service", () => { this.srcClaims = void 0 })`
  (`:786-788`). `ctx.provide` calls `reflect.notify([name])` (`cordis/lib/index.js:1403`), which emits
  `internal/service` (`:1437`). So mounting our service refreshes the claim set; no restart needed.
- Payload shape is strict. `remoteRequest` (`:1491-1504`) rejects anything but exactly one
  plain-object `args` field:

  ```js
  if (!isObject(payload) || !isPlainObject(payload) || Reflect.ownKeys(payload).length !== 1 || !Object.hasOwn(payload, "args") || !isObject(payload.args) || !isPlainObject(payload.args)) throw new Error("Remote payload must contain exactly one plain-object args field");
  ```

  and every `src-json` parameter is exempt from the "missing field" check
  (`acceptsMissing` includes `parameter.codec.mode === "src-json"`, `:1781-1782`), so `{"args":{}}`
  is valid for our zero-argument method.

**What SRC does *not* give you:** `result: { mode: "src-json" }` (`:1330`), so the result is
runtime-encoded JSON with byte detection (`encodeRpcResult`/`encodeRuntimeResult`, `:1377-1391`) —
there is no schema validation on either side. That is also true of the strict path's *client* face
here, so nothing is lost for a plain JSON ledger.

**Honest caveat:** no shipped plugin uses the SRC path. `dsh-api-gateway/README.md` calls it “a
development fallback for endpoints that have never had a strict definition”. Every ingredient above is
read from source, but the composition has not been exercised end to end by us.

## 2. Candidate 2 — an HTTP route

### 2.1 The exact route shapes (**[LIVE]** `webServer` Service)

```ts
export type WebRouteKind = 'exact' | 'prefix';
export interface WebRoute {
    kind: WebRouteKind;
    path: string;
    handler: (req: IncomingMessage, res: ServerResponse) => void | Promise<void>;
}
export type WebResource = (request: Request, peer?: PeerScope) => Promise<Response>;
export interface WebResourceRoute { kind: WebRouteKind; path: string; resource: WebResource; }
export interface WebUpgradeRoute { path: string; handler: (req: IncomingMessage, socket: Duplex, head: Buffer) => void | Promise<void>; }
```

Matching is fixed and documented: “exact over the whole table, then longest prefix, then the fallback”
(`dsh-host-webserver/README.md`). `register` returns a disposer; a duplicate `(kind, path)` throws.

### 2.2 Can the page fetch it in *this* build? Yes — with a caveat about which build this is

`dsh-host-webserver/README.md` (Summary) says:

> “It serves browsers only; **Electron loads dist over `file://` and carries fetch over an IPC
> bridge**.”

That describes a *static-desktop* carrier. In **this** session it is not the active arrangement: the
declared GUI URL is `http://127.0.0.1:54779`, and the probes in the Environment table show a live HTTP
listener answering `/` with the index gate (`authorizeIndex`) and serving `/api` route results. The
shipped client-side code confirms the same-origin assumption by building **document-relative** URLs
(`${channel}/${endpoint}`.slice(1), `client.browser.js:1221`) and defaulting to the page's global
`fetch` (`:1210`).

**Conclusion:** in this build a route reached at the GUI origin is same-origin with the page, so a
relative `fetch('/api/…')` from the page reaches it. **UNVERIFIED:** whether a *static-desktop*
(`file://`) run of DSH would instead route that fetch through the IPC bridge; if our users ever run
that carrier, a document-relative fetch is the wrong assumption and only an in-process Remote would
work. Worth one probe when the first implementation lands.

### 2.3 What `webServer.register` exposes unauthenticated — state this plainly

A raw `webServer.register` route is **not authenticated**. `dsh-host-webserver/README.md` (Known
Limitations):

> “**No server-wide authentication or origin policy** — route owners such as `dsh-client-connection`
> enforce their own request policy. Binding a non-loopback address still exposes unprotected routes
> and static assets to that network.”

The service has no peer for an HTTP resource route (“Over HTTP, the request carries no Peer”, README
§ Registering routes), so the owner must ask Connection to decide. Connection exposes exactly the two
hooks for that (**[LIVE]**):

- `requestRejection(request: ConnectionTrustRequest): ConnectionRequestRejection` — “Apply
  Connection's Host/Origin checks and browser authentication to another Web route.”
- `admit(request: ConnectionTrustRequest): PeerAdmission` — “Admit an HTTP request against its signed
  browser or API credential and live Peer.”

Exposure if we skip that: the ledger is readable by **any local process** (and by any page in a local
browser able to issue the request; a cross-origin page cannot read the body without CORS, but a
`no-cors` issue is still possible) on `127.0.0.1:54779`. It is loopback-bound, so not network-exposed —
but it is Session metadata (Session ids + upload positions), which is exactly the kind of thing this
plugin's whole design is careful about. **Do not ship an unauthenticated ledger route.**

### 2.4 The sanctioned, already-authenticated form: `ctx.connection.fetch.register`

Shipped plugins do not use `webServer.register` for this. They use Connection's exact Fetch registry
(**[LIVE]** contract):

```ts

    readonly path: string;
    readonly methods: readonly ('GET' | 'HEAD' | 'POST')[];
    readonly requestBody: 'buffered' | 'streaming';
    readonly fetch: (request: Request) => Promise<Response>;
}
export interface HostConnectionFetch { register(route: ConnectionFetchRoute): () => Promise<void>; }
```

`@deepseek-ai/dsh-session-log-export` registers two of them
(`dsh-session-log-export/lib/index.js:784,798-825`):

```js

* @param ctx - Host context carrying the human-command registry.
```

with `const SESSION_LOG_EXPORT_PATH = "/api/session.export";` (`:767`) and
`const SESSION_MARKDOWN_EXPORT_PATH = "/api/session.markdown";` (`:770`).

Routes registered here are dispatched by Connection's shared `/api` handler, which is the handler that
performs trust and browser authentication. `dsh-client-connection/README.md`:

> “The Host half always provides the carrier-neutral RPC and **exact `GET`/`HEAD`/`POST` route
> registries**. … Typert Gateway claims generated Remote endpoints, **feature packages register
> non-JSON responses such as Session-log downloads and raw file uploads**, and unclaimed requests
> return 404.”

> “A missing, expired, malformed, or wrong-authority cookie returns 401 **before RPC dispatch**.
> Static assets remain public.”

`ctx.connection.createSharedFetchHandler(channel: '/api')` is documented as “Fetch handler for
**trusted, authenticated** requests” (**[LIVE]** contract).

**Measured, not inferred:** `GET /api/session.export` with no cookie returns **401** from this session
(see the Environment table). So:
- the route is reachable from outside the page at the GUI origin, and
- it is refused without the browser credential.

That is the exposure answer for candidate 2: **`webServer.register` = public; `connection.fetch.register`
= authenticated.** Use the latter.


**Verdict on this example:** it is the sanctioned shape, and it is exactly what a build step would

pass** (§1.2). Do not treat it as a viable route; treat it as the specification of what the Remote

### 3.2 The reproducible one: a Host-owned HTTP route fetched by the Client half

`@deepseek-ai/dsh-session-log-export` is a Host+Client pair, shipped, in this build, and it moves
Host-owned data into the page with no generated contribution and no Remote at all.

**Host** (`dsh-session-log-export/lib/index.js:767-771, 798-825`): `connectionOf(ctx).fetch.register({ path: '/api/session.markdown', methods: ['GET','HEAD'], requestBody: 'buffered', fetch: … })`,
under the doc comment “authenticated ZIP download and Markdown copy routes”.

**Client** (`dsh-session-log-export/lib/client.js:11-14, 54, 248-252`):

```js
/** Browser-relative form of {@link SESSION_MARKDOWN_EXPORT_PATH}. */

…
```

zod, no markers, no `$mount`, and no `package.json` change.

## 4. Recommendation — one approach

**Register an authenticated exact Fetch route from the Host half, and fetch it from `client.js`.**

```js
// index.js — inside apply(ctx), added to the existing `disposers` array.
// `connection` is deliberately NOT added to this row's `inject`: the mode:"off" exclusion must keep
// working in a composition with no connection service (index.js export `inject`; verify/REPORT.md F5).
// Reach it optionally, exactly as host/upload.js and index.js already reach `sessions`/`credentials`.
function registerLedgerRoute() {
  const connection = ctx.get('connection')
  if (connection === undefined || connection === null || typeof connection.fetch?.register !== 'function') {
    log('warn', 'session-log-upload: the connection service is unavailable, so the Settings page cannot read the upload ledger')
    return undefined
  }
  return ctx.effect(
    () => connection.fetch.register({
      path: '/api/session-log-upload.ledger',
      methods: ['GET'],
      requestBody: 'buffered',
      fetch: async () => new Response(
        JSON.stringify({ version: 1, sessions: watermark.list() }),
        { status: 200, headers: { 'content-type': 'application/json', 'cache-control': 'no-store' } },
      ),
    }),
    'session-log-upload: upload ledger route',
  )
}
disposers.push(registerLedgerRoute())
```

```js
// client.js — inside createBridge(ctx); no new inject entry is required.
async function readLedger() {
  try {
    const response = await fetch('api/session-log-upload.ledger', { headers: { accept: 'application/json' } })
    if (!response.ok) return { status: 'unavailable', sessions: [] }
    const body = await response.json()
    return { status: 'ready', sessions: Array.isArray(body?.sessions) ? body.sessions : [] }
  } catch {
    return { status: 'unavailable', sessions: [] }
  }
}
```

**Why this one:**

1. It is the pattern two shipped plugins already use, one of them a Host+Client pair doing literally
   this (`§3.2`).
2. Authentication is inherited, not invented — measured 401 without the cookie (`§2.4`), and the route
   lives inside Connection's trusted-handler dispatch.
3. No build step, no bare specifier, no generated artifact, no zod, no decorator pass. It satisfies
   the plugin's stated constraints exactly.
4. No `package.json` change: the client uses the page's global `fetch`, and the Host reaches
   `connection` through `ctx.get` so the `mode: "off"` privacy invariant keeps working without it.
5. `path` is a free namespace under `/api/…`; there is no collision with Gateway RPC (exact Fetch
   routes win: “the handler dispatches claimed endpoints to Gateway and returns 404 for unclaimed
   requests **unless an exact Fetch route owns them**”, `dsh-api-gateway/README.md`).

**Two implementation notes for whoever builds this:**

- `WatermarkStore` currently exposes only `read(sessionId)` and `write(sessionId, value)`
  (`host/watermark.js:103,121`). A read-only listing accessor (e.g. `list()` returning
  `[{ sessionId, afterSeq, sessionFormatVersion, updatedAt }]` from `_ensureLoaded()`) must be added
  first. That is new code, not a change to the storage contract.
- Keep the response to Session ids and watermark positions. `WatermarkStore` is loaded once into
  memory (`_ensureLoaded`, `:141-159`) and capped at 512 records (`:34`), so the payload is small and
  can be returned whole — no paging needed.

**Runner-up, if we decide we want `ctx.remote.sessionLogUpload.ledger()` instead:** the SRC path in
§1.3 plus `ctx.connection.rpc.call` (§1.4 Option A). It is reachable in plain JS and gives the standard
`RemoteResult`/`RemoteError` envelope, but it has no shipped precedent, it hand-writes a
generated-artifact ABI, and `dsh-api-gateway/README.md` labels SRC “a development fallback”.

**Explicitly not viable:** `ctx.typert.register` (§1.2), any `@Remote` decorator syntax, and any
client contribution produced by the Typert generator. All three require a build step.

## 5. Fallback with zero new surface

If we would rather add no HTTP route and no Remote endpoint at all:

1. **Extend the existing Host command.** `/session-log-upload` already exists
   (`index.js`, `COMMAND_NAME` / `registerCommand`) and its bare form prints status (`statusText()`).
   A bare invocation that also prints one line per Session from the watermark table puts the ledger in
   the conversation, where the user asked for it, with no new channel and no authentication question.
   This is the cheapest honest answer and it works in every composition, including headless ones.
2. **Write a human-readable ledger file.** `host/watermark.js` already writes
   `$DSH_HOME/session-log-upload/watermarks.json` atomically at mode `0o600` (`:170-182`). A
   sibling `ledger.md` (Session id, `afterLog`, `updatedAt`, plus Session title if resolvable) is a
   two-line change and needs no UI work. Note the JSON is already human-readable — `JSON.stringify(…, null, 2)`
   (`:173`) — so this is optional.

Neither shows the state *inside the Settings UI*, which is what the user asked for. §4 is the way to
do that; §5 is what to ship if §4 is judged too much surface.
